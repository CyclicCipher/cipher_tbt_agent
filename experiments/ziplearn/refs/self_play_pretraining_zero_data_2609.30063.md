# Self-Play Pretraining with Zero Data — arXiv 2609.30063

Cowsik, Dolev, Li, De Luca, Cohen, Goodman, Levine (Independent / Tel Aviv / Stanford / LAPTh USMB), 2026.
Read 2026-09-30 from the ABSTRACT ONLY — the arXiv page fetch did not surface the body, so every number below is
one the abstract states and nothing here should be cited as if the paper's experiments had been read.

## Abstract, verbatim in substance

"Advances in language modeling have been driven by scaling pretraining on ever more data. Yet, the training data
is still largely curated on the model's behalf. A more general approach to pretraining would let the model learn
to generate the data most useful for its own improvement. This would provide an effectively unbounded source of
training data, limited by compute rather than human knowledge. We introduce **Self-Play Pretraining with Zero
Data**, an initial proof-of-concept towards realizing this vision. Our procedure casts synthetic data generation
as a search over the space of all computable structure, taking inspiration from Solomonoff induction. Starting
from random initialization, two models learn in tandem: a **generator** proposes programs interpreted by a
universal Turing machine, generating byte sequences, while a **learner** autoregressively predicts these byte
sequences. The learner is trained with standard cross-entropy, while the generator is trained with reinforcement
learning to produce sequences at the frontier of the learner's capabilities, yielding an adaptive curriculum. A
universal Turing machine gives us a search space over all computable structure, imposing little domain-specific
structure, and self-play searches over this space for useful training data. We test whether zero-shot performance
on natural data improves predictably with self-play compute; this is a clean test of transfer since neither
generator nor learner is trained on natural data. Across several natural datasets, zero-shot loss exhibits
predictable scaling in compute. The models also exhibit in-context learning, and discover recognizable
mathematical sequences during training."

## Why it matters to this project

**It is our founding premise, run as an experiment from the opposite direction.** DESIGN §19 point 3 holds that
the parameter-to-function map is biased toward simple functions, so init plus SGD samples from a Solomonoff-like
prior, and §24 states the corollary — "the world is generated by short programs" is the MDL assumption this whole
line rests on. We have been *assuming* it and building compression machinery on top. This paper trains a learner
on nothing but the outputs of short programs and reports that zero-shot loss on natural text scales predictably
with compute. That is evidence the premise is not only true but EXPLOITABLE, obtained in a way we cannot obtain
ourselves.

**It is the maximal form of the transfer result we already cite.** Papadimitriou & Jurafsky (EMNLP 2020,
`refs/`-adjacent, cited in §18.1) showed pretraining on MIDI, Java and artificial nested-bracket languages
improves Spanish, with recursion as the transferring ingredient. This says the *entire* pretraining corpus can be
synthetic if the curriculum is adaptive.

**The generator/learner split is our BrainBuilder/ZipLearn split with RL where we would use a price.** Their
generator is rewarded for producing sequences at the frontier of the learner's capability. That is learning
progress — `reference_efe_and_epiplexity`'s epiplexity, which goes to zero for both noise and mastered material —
and our idiom prices it instead of training it: **a generator scored by how much the learner's DESCRIPTION LENGTH
improves is the same object, gradient-free.** We already have that price (`ziplib/price.py`).

**And it is the cleanest in-context-learning result available.** The learner acquires ICL from programs alone —
no language, no world. So ICL is not about either: it is what you get from training on a mixture over GENERATORS
where the only way to predict is to infer which one you are in. That is Xie et al.'s implicit-Bayesian-inference
account made literal, the latent concept being an actual program. It also fits the Chan et al. recipe by
construction: a UTM's program distribution is Zipfian (short programs dominate, long tail) and bursty (one program
emits a coherent run), which are exactly the data properties reported to drive emergent ICL — and, per §24.3, the
exact regime in which counting fails.

## Honest limits (mine, not stated by the abstract)

- **Level versus trend.** "Predictable scaling" over a measured range says nothing about the absolute level or
  about continuation. The authors call it an initial proof-of-concept; it should be held to that.
- **The curriculum is where the leverage is.** Almost all UTM programs emit nothing useful — halt at once, loop
  for ever, emit constants. "Little domain-specific structure" is true of the SPACE; the RL generator is doing the
  work of finding the interesting measure-zero subset, so the result stands on that search working.
- **The distance from "Fibonacci" to "fractal Brownian motion" is enormous.** Recognizable mathematical sequences
  are the arithmetic-progression end of program space. A Perlin-class generator needs nested loops, interpolation
  and a lookup table.

## What it suggests we build — the cheapest thing it unblocks

§18's standing open question is *what compressing behaviour writes into the block*, and E42/E43 died on sample
size (21–34 changed windows per game). This paper's answer to the same problem is to GENERATE the data.

Concretely, and in our idiom: generate synthetic grid dynamics from short programs (cellular-automaton-style
rules), and test whether the written block can in-context-learn an UNSEEN rule from demonstrations. That fixes the
sample-size problem outright (unlimited changed windows), supplies ground truth (the generating rule and its
description length are known), tests ICL at the level of GENERATORS rather than windows, and lets the curriculum
be PRICED rather than RL-trained: propose rules, keep the ones where the block's description length improves
most. Pre-registration would be: held-out rule families, accuracy on changed cells against demonstrations in
context, and the description length of the rule the block effectively recovers.

## The test worth stealing: can a model in-context a generator it was never trained on?

Perlin / simplex noise is a well-chosen probe and for a reason that is not obvious. It splits cleanly into
- a SHORT PROGRAM — lattice gradients, smoothstep interpolation, octaves summed as fBm, on the order of fifty
  lines, highly compressible; and
- an INCOMPRESSIBLE SEED — the 256-entry permutation table, which has no shorter description than itself.

So a model can only in-context-learn it by FACTORING generator from parameter: the class has to come from
pretraining, the seed has to be read from the context, and the values cannot be memorised. That makes it a
factorization test one level above the one E44 just ran — our mask asks which CELLS are relevant, this asks which
part of the data is PROGRAM and which is SEED. It is also unusually measurable: the generator's description length
is known and the fBm spectrum sets an irreducible entropy floor, so one can report how close the model came to the
true conditional entropy rather than only that accuracy rose.

A benchmark follows: held-out program families (Perlin/fBm, cellular automata, L-systems, chaotic maps,
reaction-diffusion), each with a known description length, scored by in-context transfer. That is a far better
probe of how well a trained net approximates the universal prior than few-shot classification, because the ground
truth is a program.
